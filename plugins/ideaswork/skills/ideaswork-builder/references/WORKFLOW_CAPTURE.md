# 从已完成的工作沉淀 Skill

## 触发与目标

用户明确要求把刚才通过 Capability 或 Runner 完成的流程做成可复用 Skill 时读取本节。
不是因为连续调用多个 API、产生了脚本或生成了多个产物就自动构建；先尊重用户当前的实际任务。
把一次成功实践提炼成参数化流程，不机械复制对话，不要求先选择 Builder 角色。

## 承接最小证据

复用当前对话、已返回的平台记录和实际文件，整理到独立草稿的 `SKILL_BUILD_FINDINGS.md` 或既有 `.avp_gaps.json` 台账中（上传时排除）：

- 原目标、完成判据及已确认的用户选择。
- 有效的 API code、调用顺序/依赖、查过的 schema 和请求/响应摘要。
- 参数来源：用户输入、上一步结果、固定业务规则；重要的 prompt/参数调整。
- 工作区、真实任务 ID、产物引用和异步终态证据。
- 成功路径、失败尝试、最终采用的修正，以及仍未验证的分支。

只记录能实际找到的证据，不能补造工具调用 ID、成功响应或任务完成状态。
本地构建说明不存凭据，不包含完整隐私数据，不作为业务运行资源或上传内容。
既有上下文/文件足够就不再次检索；确需历史时只用服务端实际提供且获授权的入口，不猜新工具。

## 提炼而不是复制

1. 把一次性的素材/对象 ID、输出路径和数量改为输入参数或运行时结果引用；保留明确的业务固定规则。
2. 只把最终采用的成功路径写入主流程；失败分支用于必要的错误处理，不把所有试验串成工作流。
3. 补齐适用范围、前置条件、输入输出、数据传递、异步等待与异常退出。
4. 既有远端 Skill 用独立草稿转化，不覆盖 immutable checkout；已有成果但没有具体 Skill 时按 sampling。
5. `api.json` 如实登记目标流程调用的 API；它不是授权申请，不能借本地声明取得垂类/策略 API 权限。

## 复用验证

对证据足够、schema 仍匹配、核心参数/编排未改变的步骤，直接沿用成功请求和结果摘要。
只为缺失证据或改变后的关键步骤补充低成本验证。API 当前权限仍需核对，历史成功不授予新 Context 权限。
只有提交响应的异步调用标为“已提交/待确认”，无终态不能标为已完成；未测分支标为待验证。
付费生成、批量扩大、删除覆盖不为“再证明一次”默认重跑，按既有授权规则先确认新增动作。

## 阶段与交付

沿用 01–06 渐进加载：01 承接上下文，02 核对调用与文档，03 参数化设计，04 复用证据/补验证，
05 生成并静态校验，06 收口真正的限制。只询问影响复用范围或交付的缺失信息。
先交付可用本地 Skill；用户明确要求提交时再检查服务端 Tool、scope 与业务权限。
没有写入权限或提交入口时仍交付本地草稿，正式发布不是自动步骤。
